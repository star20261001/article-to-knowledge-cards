# Make Knowledge Cards

从一篇文章中提取真正值得记住的知识点，生成格式统一的 Markdown 知识卡片。卡片是给人复习用的，不是文章摘要的分段——每张卡片必须独立成立，脱离原文也能看懂。

## 支持的输入

- 用户直接粘贴在对话里的文章正文。
- 本地 `.md` / `.txt` 文件：用文件读取工具按绝对路径读取。

遇到不支持的输入（网页链接、PDF、图片、Word 等），不要猜测内容，直接说明本技能只处理正文文本和 Markdown/TXT 文件，并建议用户先转换或粘贴正文。

## 工作流程

1. **通读全文**，确认文章的主要话题和信息密度，判断原文语言（输出语言跟随原文，除非用户另有要求）。
2. **提取候选知识点**。值得提取的：概念定义、可操作的规则或步骤、有数据支撑的结论、容易混淆的区别、反直觉的事实。不值得提取的：开场铺垫、作者自述、重复表述、只有态度没有信息的观点。
3. **去重与合并**。同一知识点的多处表述合成一张卡；两张卡内容明显重叠时合并或换角度重选。
4. **确定数量**。目标区间 5~8 张，一张卡对应一个独立知识点，按实际提取结果决定：
   - 5~8 个知识点 → 逐点成卡；
   - 超过 8 个 → 按重要度取前 8，全部卡片结束后附一行"原文还谈及：<被舍弃的主题>"；
   - 少于 5 个 → 按实际数量输出（可以只有 2~4 张），绝不拆碎或注水凑数，并在来源行后注明"原文可提取的独立知识点有限"。
5. **逐张撰写**，按下面的卡片模板填写。
6. **交付前自检**（对照原稿逐项检查，不通过就修改）：
   - 每张卡只讲一个知识点：问自己"这张卡能不能用一句不含'和/另外'的话概括"，不能就拆开或删掉多余部分；标题要短（中文约 10 字内，英文约 6 词内），直接点出知识点本身；
   - 卡片里每个事实性表述都能在原文找到依据，没有编造；
   - 没有两张卡内容重复；
   - "例子或自测问题"与核心知识严格对应。

## 卡片模板

```markdown
### 卡片 N：{标题}

**核心知识**：{一句话结论，忠实于原文}

**简明解释**：{2~4 句，把结论讲透：为什么、怎么做、边界条件}

**例子 / 自测问题**：{二选一，见下方规则}
```

"例子 / 自测问题"的取舍规则（每张卡只放其中一种，不要混排）：

- 原文本身给了例子、数字、场景 → 放原文的例子（可压缩措辞，但事实不变）。
- 原文只有概念没有例子 → 放 1 道自测问题，且必须能仅凭本卡内容回答；不要出需要外部知识才能答的题。
- 为便于理解而补充构造的例子，必须标注"示意例子（非原文提供）"，与原文事实区分开。

## 输出形式

- **默认输出**：直接在对话里输出全部卡片，开头加一行"来源：《文章标题》· 共 N 张卡片"（英文文章用对应语言："Source: <title> · N cards"）。
- **保存文件**：用户要求保存时，除对话输出外再写成单个 UTF-8 Markdown 文件（如 `知识卡片-<主题>.md`），文件内容与对话输出一致（含来源行与任何说明句）。
- **卡片内语言**：跟随原文。英文文章用 `**Core idea** / **Explanation** / **Example / Self-test**` 这类对应标签，模板结构不变。

## 边界情况

- **文章太短或信息量低**：按工作流程第 4 步"少于 5 个"的规则处理，不另设口径。
- **多主题长文**：按主题聚簇成卡，跨主题的综述句不单独成卡。
- **观点型/情绪型文章**：只提取有信息量的论断；纯态度表达不成卡，并向用户说明该文章适合提取的事实很少。
- **表格、清单类原文**：每一行/每一项通常是独立知识点，优先提取规则与例外，说明性套话不成卡。

## 硬性约束

- 不编造原文没有的事实、数字、引用。原文没说的，宁可留白或用自测问题代替，也不补全。
- 引用原文数字与限定词（时间、范围、程度副词）时保持原口径，不把"多数研究发现"写成"研究证明"。
- 不复述全文结构做流水账卡片；卡片数量由知识点决定，不由段落数决定。
